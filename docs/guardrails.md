# Guardrail enforcement matrix

Every guardrail is a backend control: it holds even if a model ignores its prompt. Each row names the code that enforces it and the automated tests that check it.

| # | Guardrail | Enforced by | Verified by |
|---|---|---|---|
| 1 | **Identity.** Every encounter belongs to a verified patient; returning patients are matched, new ones registered once. | Patient Registry agent (`agents/medibridge_agents/nodes/registry.py`): an MRN is accepted only with the matching date of birth (a mismatch is refused and audited, never 'closest match'); name + date-of-birth searches return ranked candidates; registration shows likely duplicates (same date of birth, similar name) before creating a record and requires confirmation; desk registrations get their own MRN range and record who registered. `clinical.encounters.patient_id` is NOT NULL with a foreign key; a trigger forbids moving an encounter to another patient. `POST /encounters/{id}/verify-identity` requires MRN **and** date of birth. The registry check step blocks the run until identity and both consents are recorded. | `tests/backend/test_registry.py`, `tests/backend/test_encounters.py`, `tests/backend/test_db_controls.py::test_encounter_cannot_move_to_another_patient`, `tests/workflow/test_workflow.py::test_consent_is_required_before_a_run`, e2e `nurse: patient registry ...` |
| 2 | **Authorization.** Role and patient scope are checked on every read. | `security/deps.py` provides `require(permission)` and `ensure_patient_scope`; out-of-scope access returns 404 and is audited. The admin role has no patient-scoped permission. Every MCP and agent tool call re-checks RBAC, care-team scope and the id match (`agents/medibridge_agents/tools.py`). Qdrant searches need a server-resolved patient UUID, and Postgres re-checks every hit. | `tests/security/test_patient_isolation.py`, `tests/backend/test_rbac.py`, `tests/backend/test_documents_pipeline.py::test_retrieval_drops_chunks_from_other_patients`, `tests/security/test_mcp.py` |
| 3 | **Handoff privacy.** | Allow-list serializers (`services/clinical_views.py`) with no serializer for contacts or administrative IDs. Administrative IDs are admin-only and need a stated reason. A deterministic identifier scanner (`guardrails/phi.py`) runs on document text before display, indexing for display, and handoff assembly; a final scan must come back clean or the draft is blocked. Original PDFs need a stated reason and are audited. The handoff is labelled a named clinical handoff, `anonymized: false`. | `tests/backend/test_documents_pipeline.py` (identifier and clinical-value cases), `tests/security/test_patient_isolation.py::test_contacts_never_appear_in_clinical_views`, `tests/workflow/test_workflow.py::test_full_workflow_with_three_human_gates` (labels) |
| 4 | **Hallucination prevention.** | NER requires a verbatim source phrase for every item; invalid items are quarantined, never used. | 5 | **Medication safety.** | Deterministic Neo4j screen (`knowledge/medibridge_knowledge/graph.py`) over the cardiology release: public-domain RxNorm, MED-RT and FDA EPC plus 66 label-quoted interactions and 2 drug-condition cautions (the build refuses any quote not found verbatim in the FDA label). MED-RT condition links are coarse (heart failure is listed for the beta-blockers that treat it), so they are only ever a non-blocking caution. Allergies outside the cardiology scope are listed as not screened. **The doctor's proposed orders are screened before anything is written** (Order Entry -> Medication Safety, agent-to-agent); orders that cannot be identified are blocking. The result is never 'complete' and never claims safety. | `tests/backend/test_knowledge.py` (dose limits, brand names, condition cautions, MED-RT never blocks, combination split, out-of-scope allergy), `tests/workflow/test_workflow.py` (orders screening, unscreenable order) |
| 6 | **No autonomous prescribing.** | No code path turns model output into a prescription. A CHECK constraint requires approval for active prescriptions. | `tests/backend/test_db_controls.py` (nurse prescriber, approval for another patient, missing approval), `tests/workflow/test_workflow.py::test_prescription_requires_alert_acknowledgement` |
| 7 | **Human approval.** | Four LangGraph `interrupt()` gates: transcript review, brief review, note and orders, safety review. Approvals bind to the exact version's SHA-256. | 9 | **Trace protection.** | LangSmith is off by default and needs an explicit endpoint. | 10 | **Clinical uncertainty.** | Negation and certainty fields are cross-checked against NegEx-style rules. Source kind, certainty and age travel with every fact. | 11 | **Emergency escalation.** | Configurable, negation-aware rules (`agents/medibridge_agents/escalation_rules.json`, demo rules, not clinically validated). | 12 | **Auditability.** | Append-only `audit.audit_logs`. The hash chain is computed by a BEFORE INSERT trigger under an advisory lock. | 13 | **Agent-to-agent boundary** (added with A2A; peer calls added in phase 2). Agent side (`server.py`): the RPC endpoint returns 401 without a valid, unused token for this agent (audited `a2a.capability_rejected`); the task is rejected if the skill is not offered, the state ids differ from the token, or extra input keys were sent (audited `a2a.task_refused`). The agent then runs with a run context built from those ids, so the tool layer's permission and id checks (row 2) apply inside every agent. Agent ports bind to loopback only (validated at startup). | `tests/security/test_a2a.py` (missing, forged, expired, wrong-agent and replayed tokens; another patient's state; skill not offered; over-sharing; rogue agent writing `review`; supervisor sends only allowed keys; agent down), `tests/workflow/test_workflow.py::test_specialist_steps_run_over_a2a`, `::test_a_critical_agent_that_is_down_fails_the_run`, `::test_a_non_critical_agent_that_is_down_degrades_and_is_stated` |
| 14 | **Pre-generation checks** (Clinical Handoff Brief). | Before the model is asked anything, `nodes/handoff.py::preflight` checks: findings come from the human-reviewed transcript; every item is quoted verbatim; the chart loaded; reconciliation state; report search and medication screen status; instruction-like text in the transcript (counted by the Ambient Scribe, which is the only agent that sees it) or in sources (`guardrails/injection.py`); identifiers in the inputs. A `fail` blocks the brief; warnings are shown in it. | `tests/workflow/test_workflow.py::test_full_workflow_with_orders_safety_review_and_after_visit_summary` (injected instruction flagged, not followed), `::test_document_and_knowledge_outages_degrade_and_are_stated` |
| 15 | **Patient-facing summary.** | The After-Visit Summary contains this visit only. Medicine lines are rendered from the doctor's order fields (no model writes a dose); the plain-language next steps are validated (every number and medicine must come from the doctor's plan or orders; no identifiers), otherwise the plan is shown verbatim; the safety-net advice is a fixed clinic template. Released only by a doctor, hash-bound and audited. | `tests/workflow/test_workflow.py` (no history in the summary, release) |
| 16 | **Hybrid retrieval stays within one patient.** | BM25 runs only over the patient's own current chunks from Postgres; dense search is filtered to the patient in Qdrant; every fused candidate is re-validated in Postgres (patient, current version, active document) and redacted. If the dense index is down, retrieval continues lexically and reports `lexical_only`. | `tests/backend/test_documents_pipeline.py` (other-patient chunk dropped, lexical fallback, per-ranker ranks), retrieval eval leakage check |

## Known limits of the guardrails

- **Identifier scanning** is pattern-based. It catches the formats used in this demo (phone, email, US-style addresses and postcodes, SSN-like numbers, the synthetic insurance and national-ID formats). It will miss free-text identifiers such as relatives' names or uncommon address formats. A production deployment needs a validated de-identification component.
- **Escalation rules** are a small demo set, not a triage system.
- **Interaction screening** covers 65 cardiology ingredients and 66 curated interactions. Absence of an alert is explicitly not evidence of safety, and the UI says so.
- **A2A trust.** All agent services read the same `.env`, so they share the token secret and the database credentials. A token proves it came from a MediBridge process on this machine, not specifically from the supervisor, and a compromised agent process could read the database directly. Per-agent database roles and per-agent keys (or mTLS) would close this; they are not implemented. Traffic is plain HTTP on loopback.
- **Tamper evidence** detects modification by anyone who cannot also rewrite the whole chain consistently. A database superuser could still disable the trigger and recompute it. Anchoring the head hash outside the database would close this gap; that is not implemented.
